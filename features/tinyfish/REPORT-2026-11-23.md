## What Rohan wanted

TinyFish THROUGH Monid, not a direct TinyFish key. He added a Monid key for this.
Monid's TinyFish tool page (`monid.ai/tools/tinyfish`, "PROMOTIONS & FREE TIERS") lists
exactly two free endpoints. ONLY these two are to be used. The paid TinyFish
endpoints on Monid must NEVER be called.

## Why the old skill failed

The saved key is a Monid key (35 chars, prefix `moni`). The TinyFish skill v2
called TinyFish's direct API (`https://api.search.tinyfish.ai`,
`https://api.fetch.tinyfish.ai`, `X-API-Key`) → `401 INVALID_API_KEY`.
A Monid key is not a TinyFish key. The fix is to route through Monid, not to
get a TinyFish key.

## The two free endpoints (only these)

| Endpoint | Method | Input | Price (verified 2026-11-22 via `monid inspect`) | Allowed |
|---|---|---|---|---|
| `/free/search` | GET | `--query` (JSON, required `query`, 13 params) | `$0.00` PER_CALL — 30/min, 500/hour per workspace | YES |
| `/free/fetch` | POST | `-i` (JSON, required `urls` 1–10, 12 params) | `$0.00` PER_RESULT — 150 URLs/min, 1,000 URLs/day | YES |
| `/search` | — | — | `$0.00175` PER_CALL | NO — hard-blocked |
| `/fetch` | — | — | `$0.001` PER_RESULT | NO — hard-blocked |

Both free endpoints have `additionalProperties: false`. The `--query` vs `-i`
split is the trap — the CLI rejects the wrong one. Schemas were captured from
`monid inspect`, not guessed, and are recorded in full in `SKILL.md` v3.0.

Route (the whole skill):
```bash
monid run -p tinyfish -e /free/search     # web search (free)
monid run -p tinyfish -e /free/fetch      # page fetch (free)
```

## The key

Environment variable **`TINYFISH_API_KEY`**. Despite the name it holds a **Monid**
key (prefix `moni`/`monid_live`), NOT a TinyFish key. Do not "fix" it by getting
a TinyFish key — a TinyFish key cannot be used here, and the direct TinyFish
API is not part of this skill at all.

Set in Console → **Settings → Environments** ("+ Add Variable", name
`TINYFISH_API_KEY`, paste the Monid key from app.monid.ai, then Save). The
console backend writes it, encrypted, to `working.secret/envs.json` (mode 600)
and syncs it into the running process environment at once — no restart.
The skill reads `TINYFISH_API_KEY` from env and bootstraps a private `0700`
credential store via `XDG_CONFIG_HOME` — the key never enters argv.
**The vault is NOT used for this key** (vault holds only connectors).
